### SECTION 2 — Nemotron-3-Content-Safety (multimodal, 12 langs)
### =====================================================

The Nemotron-3 model uses a chat template with two kwarg families:
- `request_categories`: "/categories" (emit category list) or "/no_categories" (binary only)
- `request_reasoning`: "/think" (reasoning trace) or "/no_think" (no trace)

These combine orthogonally. The skill emits each combination cleanly.

=== PATTERN D — VANILLA SAFETY (Nemotron 3, text, /categories) ===

Safety Categories:
{{CATEGORY_NAMES_BLOCK}}

Allow-list (explicitly permitted even if adjacent to a category above):
{{ALLOW_LIST_BLOCK}}"""},
    {"role": "user", "content": "{{USER_PROMPT}}"},

inputs = processor.apply_chat_template(

Image preparation:

- 896x896 squares (SigLIP encoder); larger images are auto-resized.
- Single image per user turn.
- Categories that have visual signals (Violence, Sexual, Sexual (minor), Hate/Identity Hate, Guns and Illegal Weapons, Suicide and Self Harm, PII/Privacy when faces or IDs are visible, Malware when screenshots show exploit code) should populate the `modality_notes` field in the JSON policy describing what the visual cue looks like.

\=== NEMOTRON-3 OUTPUT FORMATS ===

Today (released March 2026):

/categories: User Safety: <safe/unsafe> Response Safety: <safe/unsafe> (if response was provided) Safety Categories: , , ... (only if unsafe)

/no_categories: User Safety: <safe/unsafe> Response Safety: <safe/unsafe> (if response was provided)

With both flag families combined:

/think + /categories:

```javascript

User Safety: <safe/unsafe>

Safety Categories: <name1>, <name2>, ...
```

/think + /no_categories:

```javascript
[reasoning trace]

```

/no_think + /categories: User Safety: <safe/unsafe> Response Safety: <safe/unsafe> Safety Categories: , , ...

/no_think + /no_categories: User Safety: <safe/unsafe> Response Safety: <safe/unsafe>
